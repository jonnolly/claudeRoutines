## Tip: stop re-typing your rules — make them a hook

### What I noticed in your own backlog
Your ✂Trace Trimmer task *"reduce start-up time"* says:

> *"Make a rule that will definitely see whenever I start claude in this folder that the start-time
> must always be under 1 second. Test this each time you make a change. If it doesn't fulfill this
> requirement, you must keep trying until you do fulfill this requirement."*

That is exactly the right instinct — a permanent invariant plus a verification loop. But it's written
as **prose inside a one-off prompt**, so it only exists in sessions where you remember to paste it.
You're paying for it in typing and tokens every single time, and it silently disappears the day you don't.

### Why a hook and not CLAUDE.md
- `CLAUDE.md` is **advisory context** loaded at session start. Community testing puts adherence around
  80% — fine for conventions, not for a hard requirement you care about.
- **Hooks** in `.claude/settings.json` are shell commands the harness runs itself, regardless of what
  the model decides. That's deterministic enforcement, not a request.
- Crucially, a failing hook hands Claude an **error it can iterate against**. Giving the agent a
  testable exit condition is the single most-cited reliability lever in agentic coding — it's the
  difference between "please check" and "this cannot pass until it's true".

### Do this (10 min)
**1. Write the check as a script that exits non-zero over budget** — `scripts/check_startup.py`:
measure cold start, print the actual number, `sys.exit(2)` if it's ≥1.0s. Print the measured time
either way, so the failure message is self-explanatory.

**2. Wire it as a `PostToolUse` hook** in `.claude/settings.json` in the Trace Trimmer repo:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          { "type": "command", "command": "python scripts/check_startup.py" }
        ]
      }
    ]
  }
}
```

Exit code 2 feeds stderr back to Claude, so it sees the regression *in-loop* and fixes it before
handing back to you — no "keep trying until you fulfill this" needed in the prompt.

**3. Then delete that paragraph from your TickTick tasks** and leave one line in `CLAUDE.md`:
`Cold start must stay under 1s — enforced by scripts/check_startup.py.` The *why* goes in CLAUDE.md;
the *teeth* go in the hook.

### Two gotchas
- Use **`PostToolUse`, not `Stop`** — Claude Code force-ends a turn after 8 consecutive `Stop`-hook
  firings, so a `Stop` hook that keeps blocking strands the session.
- Keep the check **fast** (<2s). It runs on every edit; a slow hook taxes every single loop.

### Payoff
The requirement outlives every session, every model change, and every prompt you forget to paste —
and Claude self-corrects against it instead of you reviewing for it. This is the same move for *any*
rule you've typed twice: lint, formatting, "don't touch the parser", test-must-pass.
