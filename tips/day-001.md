# Day 1 — Stop writing requirements in prose. Wire them as a gate.

**Time to adopt: ~12 minutes. One-off. Pays back on every Trace Trimmer session after it.**

## This is your own text

From the Trace Trimmer start-up-time task in TickTick:

> "Reduce the start-time to under 1 second. **Make a rule that will definitely see whenever I start
> claude in this folder** that the start-time must always be under 1 second. **Test this each time you
> make a change.** If it doesn't fulfill this requirement, **you must keep trying** until you do
> fulfill this requirement. If you can't you have to let me know and let me know the new start-time."

You described, almost exactly, the three mechanisms Claude Code has for this — in prose, inside a task
description, where it gets read once and then forgotten the next session. Each sentence has a real home:

| What you wrote | Where it actually belongs |
|---|---|
| "a rule that will definitely see whenever I start claude in this folder" | **`CLAUDE.md`** in the repo root — loads automatically at session start, every session |
| "test this each time you make a change" | a **`PostToolUse` hook** on `Edit|Write` — runs outside the model's control, so it can't be skipped |
| "you must keep trying until you fulfil this requirement" | a **`Stop` hook** — exit code 2 refuses to let the session end and hands the failure back to Claude |
| "let me know the new start-time" | the check's own output — print the measured number, always |

The distinction worth keeping: **"never do X" in CLAUDE.md is a request. A hook is a guarantee.**
CLAUDE.md informs judgement; hooks run deterministically whatever the model decides. Prohibitions and
gates belong in hooks. Facts and conventions belong in CLAUDE.md.

## The 15-minute version

1. Write the check first — the smallest script that measures cold start-up and exits non-zero when it
   is over budget. Something like `scripts/check_startup.py`: time the launch, print
   `startup: 0.83s (budget 1.00s)`, `sys.exit(1)` if over. It has to be *runnable*, not describable.
2. Then, in Claude Code, in the Trace Trimmer folder, say:

   > Add a CLAUDE.md with the build/run commands and the rule that cold start-up must stay under 1
   > second, measured by `scripts/check_startup.py`. Then use the update-config skill to add a
   > PostToolUse hook on Edit|Write that runs that script, and a Stop hook that blocks stopping while
   > it fails. Show me the settings.json diff before applying it.

   Let it write the config — `/update-config` knows the current `settings.json` schema and hook event
   names, which saves you reading the docs.
3. Break it on purpose once. Add a deliberate 2-second sleep and confirm the session *refuses* to
   finish. An ungated gate is worse than none, because you'll trust it.

## Why this one is first

Every "run more agents in parallel", "let it work continuously", "use subagents" tip you asked about
rests on this. Unattended work is only worth having if something other than the model's own opinion
decides whether it worked. A machine-checkable definition of done is that something. Without it, more
agents just means more unverified output to review — which costs you time rather than buying it.

It also generalises past start-up time: the same shape covers "the insight-converter filename parser
must still round-trip", "the GUI must still launch headless", "no test may be skipped to go green."

## Not for me to schedule

If this looks right, put it in your own calendar — it wants one quiet 15-minute slot, not a slot
carved out of a work block. Good candidate: an Admin Power Hour, or the Sunday train.
