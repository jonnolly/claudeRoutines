# Tip 1 — Mon 28 Sep 2026

## Stop re-typing the quality contract into every task

**Evidence this is yours, not generic advice.** Your Trace Trimmer startup-time ticket says:

> "Make a rule that will definitely see whenever I start claude in this folder that the
> start-time must always be under 1 second. Test this each time you make a change. If it
> doesn't fulfil this requirement, you must keep trying until you do fulfil this requirement.
> If you can't you have to let me know and let me know the new start-time."

That is a *definition of done* — test after each change, iterate until met, report the number
if you fail. You wrote it into one ticket. It should apply to every ticket in that repo, and
you shouldn't have to type it again. You even asked for the mechanism ("make a rule that will
definitely see whenever I start claude in this folder") — that mechanism is `CLAUDE.md`, which
Claude Code reads at the start of every session in that folder.

**Why it's the first tip.** Everything you asked about — multiple agents, assigned roles,
agents working continuously — only pays off if an agent can tell for itself whether it's done.
Without a machine-checkable bar, parallel agents just produce more work for you to verify.
This is the cheapest reliability win available and it's the precondition for the rest.

## Do this (≈10 minutes)

In the Trace Trimmer repo, run `claude` and ask for a `CLAUDE.md` containing roughly:

```markdown
## Definition of done
A change is not finished until:
1. The app still launches, and cold start-up is **under 1 second**. Measure it, don't estimate.
2. You have run the measurement yourself after your final edit — not before it.
3. If the bar isn't met: keep iterating. If you genuinely cannot meet it, stop and report the
   actual number you achieved and what's blocking it. Never report done with the bar unmet.

## How to measure start-up
<the exact command you use>

## Non-negotiables
- Never report success on something you did not run.
- If a requirement in the task conflicts with this file, ask before choosing.
```

Two things make the difference between this working and not:

- **Give it the exact measuring command.** "Check the start-up time" is a wish;
  `python -X importtime -c "import app"` or a timed launch script is a test. If no such
  command exists, that's the 10 minutes well spent — ask Claude to write one first.
- **Keep the file short.** Under ~200 lines. Long CLAUDE.md files get diluted and ignored;
  path-scoped `.claude/rules/*.md` files are the place for anything that only applies to
  part of the tree.

## How you'll know it worked

Next time you hand over a Trace Trimmer task, write only *what* you want and leave out all the
"test it and keep trying" scaffolding. If the result comes back with a measured number
unprompted, it's working. If it doesn't, the bar isn't machine-checkable yet — fix the command,
not the prose.

remembered — a hook that runs the check after every edit, so it isn't optional. That's tip 2.
