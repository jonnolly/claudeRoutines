# Tip 01 — 2026-10-01

## Stop writing the same rule into every task. Write it once, into `CLAUDE.md`.

**Time: ~10 minutes. Project: Trace Trimmer.**

### Why you, why this one

In your Trace Trimmer backlog you wrote this to Claude:

> "Make a rule that will **definitely see whenever I start claude in this folder** that the start-time must
> always be under 1 second. Test this each time you make a change. If it doesn't fulfill this requirement,
> you must keep trying until you do fulfill this requirement."

You correctly identified the exact thing you needed — persistent, always-loaded project memory — and then
hand-built it in prose, inside one task, where it will only ever apply to that task. Every new session starts
cold again and you pay the explanation tax a second, third, fourth time.

`CLAUDE.md` is that mechanism, built in. It sits in the project root, and Claude Code reads it automatically at
the start of **every** session in that folder. Write the rule once; it's enforced forever. Of all the practices
being written up in 2026, this is consistently called the highest-ROI one, precisely because it compounds — it's
the only one that gets *more* valuable the longer you use it.

### Do this now

In the Trace Trimmer repo root, create `CLAUDE.md`:

```markdown
# Trace Trimmer

Desktop GUI tool for trimming CAN-bus trace files.

## Hard requirements — never regress these
- Application start-up time MUST be under 1 second. Measure it after any change that
  touches imports, startup, or the GUI construction path. If a change pushes it over,
  fix it before reporting done. If you genuinely cannot, stop and tell me the new number.

## File formats
- "Insight" traces: line 4 of the file contains "generated by insight can converter".
  Header lines start with `;`. For these, start/end time come from the FILENAME, not the
  contents: `can_log_[ip]_[startUnix]_[endUnix]`
  e.g. `can_log_10.105.60.1_1759879140_1759880340`

## How I work
- Show me a short plan before changing more than one file.
- Keep changes minimal and scoped to what I asked.
- Run the app and confirm it starts before telling me a change is done.
```

Then: `git add CLAUDE.md && git commit -m "Add project memory for Claude"`

### The 30-second version if you only have 30 seconds

Open Trace Trimmer in Claude Code and type: **`/init`**. It drafts a `CLAUDE.md` by reading the codebase.
Then paste the "Hard requirements" and "File formats" blocks above into it, because those are the parts it
can't infer. Commit it.

### How you'll know it worked

Next session in that folder, you won't have to mention the 1-second rule or the insight-file format.
Every time you catch yourself re-explaining something to Claude, that's a line that belongs in this file.
The file is the asset — the sessions are disposable.
