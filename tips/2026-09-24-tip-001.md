# Tip 001 — Stop writing rules in prose. Make them exit non-zero.

**Theme:** verification loops · **Time:** ~12 min · **Why you:** taken from your own words

## What I noticed

In your Trace Trimmer backlog you wrote this, to Claude:

> "Reduce the start-time to under 1 second. **Make a rule that will definitely see whenever I
> start claude in this folder** that the start-time must always be under 1 second. **Test this
> each time you make a change.** If it doesn't fulfill this requirement, **you must keep trying
> until you do.**"

That's three different Claude Code primitives, hand-rolled in English:

| What you asked for | The primitive that does it |
|---|---|
| "a rule it will definitely see whenever I start claude here" | `CLAUDE.md` at the project root — read automatically every session |
| "test this each time you make a change" | a check script, optionally wired to a hook |
| "keep trying until you fulfil it" | a verification loop — but only works if there's a pass/fail signal |

The catch is the third one. **"Keep trying until it's under 1 second" is unenforceable if nothing
measures the second.** Claude will report success in good faith and you find out later. The
single highest-leverage change available to you right now is converting that sentence into
something that exits non-zero.

## Do this (~12 minutes)

In the Trace Trimmer repo — or whichever project is live right now:

**1. Write the check (~6 min).** Something crude is fine. It only has to be honest:

```bash
# scripts/check_startup.sh
BUDGET=1.0
START=$(date +%s.%N)
# ...launch the app to the point it's interactive, then exit...
ELAPSED=$(echo "$(date +%s.%N) - $START" | bc)
echo "startup: ${ELAPSED}s (budget ${BUDGET}s)"
[ "$(echo "$ELAPSED < $BUDGET" | bc)" -eq 1 ] || { echo "FAIL: over budget"; exit 1; }
```

**2. Point CLAUDE.md at it (~3 min).** Three lines beat three paragraphs:

```markdown
## Invariants
- Startup must stay under 1s. Verify with `./scripts/check_startup.sh` after any change
  touching startup. Do not report a change as done until this passes.
```

**3. Ask for the number, not the verdict (~3 min).** From now on, end requests like this with
*"run check_startup.sh and paste the output"* rather than *"make sure it's fast"*.

## Why this is first

Everything else you mentioned wanting — multiple agents, assigned roles, agents running
continuously — **multiplies whatever process you already have.** Parallel agents on an unverified
process produce wrong work faster. A mechanical pass/fail is what makes unattended work safe, so
it has to come first. We'll get to the multi-agent material; this is the foundation it stands on.

The research backs the sequencing: the most-cited recent result is METR's RCT, where experienced
developers were **19% slower** with AI on familiar code — while believing they'd been faster.
Self-reported success is the failure mode. Mechanical checks are the fix.

## The 30-second version

Any requirement you've written to Claude as prose — "always", "must", "keep trying until" — is a
requirement with nothing behind it. Pick the one that would hurt most if it silently broke, and
give it a script that exits non-zero.
